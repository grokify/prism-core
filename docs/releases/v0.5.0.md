# Release Notes v0.5.0

This release adds a thin, ecosystem-shared primitive for referencing capabilities, so any PRISM module can point at a capability the same way without depending on prism-capability's full domain model.

## New Features

### Capability References (`capability.go`)

Added `CapabilityRelation` constants describing how one entity relates to a capability:

- `CapabilityRelationEnables` - the referencing entity creates a capability that did not exist before
- `CapabilityRelationImproves` - the referencing entity strengthens an existing capability without creating a new one
- `CapabilityRelationDependsOn` - the referencing entity requires an existing capability to be in place before it can proceed

And `CapabilityRef`, a thin shape (`CapabilityID`, `Relation`, `Rationale`) any PRISM module can embed or reference to point at a capability without pulling in prism-capability's full domain model (`CapabilityStack`, `Layer`, `Category`, and so on).

### New Helper Functions

- `AllCapabilityRelations()` - Returns all capability relation constants
- `ValidCapabilityRelation()` - Checks if a relation value is valid
- `CapabilityRelationDisplayName()` - Returns a human-readable name for a relation

## Usage

```go
import prism "github.com/grokify/prism-core"

ref := prism.CapabilityRef{
	CapabilityID: "authorization",
	Relation:     prism.CapabilityRelationEnables,
	Rationale:    "introduces fine-grained authorization for enterprise customers",
}

if prism.ValidCapabilityRelation(ref.Relation) {
	name := prism.CapabilityRelationDisplayName(ref.Relation)
	// Returns: "Enables"
}
```
