# PRISM Core v0.1.0

**Release Date:** 2026-05-18

Initial release of PRISM Core, providing shared primitives and types for the PRISM ecosystem.

## Overview

PRISM Core is the foundational library for the PRISM ecosystem, providing common types and constants used across:

- [PRISM Capability](https://github.com/grokify/prism-capability) - What we need
- [PRISM Intelligence](https://github.com/grokify/prism-intelligence) - How we measure
- [PRISM Execution](https://github.com/grokify/prism-execution) - How we act

## Features

### Domain Types (`domain.go`)

10 domain constants for categorizing capabilities and metrics:

- `DomainSecurity` - Security and compliance
- `DomainOperations` - Operations and reliability
- `DomainQuality` - Quality and testing
- `DomainPlatform` - Platform and infrastructure
- `DomainAI` - AI and machine learning
- `DomainData` - Data management
- `DomainProduct` - Product management
- `DomainEngineering` - Engineering practices
- `DomainCompliance` - Regulatory compliance
- `DomainCustomer` - Customer experience

Helper functions: `AllDomains()`, `ValidDomain()`

### Status Types (`status.go`)

Document and workflow status enumerations:

- **Document Status**: Draft, In Review, Approved, Active, Deprecated, Archived
- **Health Status**: Green, Yellow, Red
- **Priority**: Critical, High, Medium, Low
- **MoSCoW**: Must, Should, Could, Won't
- **Capability Status**: Planned, In Progress, Implemented, Operational, Deprecated

Helper functions: `AllDocumentStatuses()`, `AllHealthStatuses()`, `AllPriorities()`, `AllMoSCoW()`, `AllCapabilityStatuses()`

### Metadata (`metadata.go`)

Common metadata structure for PRISM documents:

```go
type Metadata struct {
    ID, Name, Title, Description, Version string
    Status, Domain, Owner, Team string
    Authors []Person
    Tags []string
    CreatedAt, UpdatedAt time.Time
}
```

### Person & Team Types (`person.go`)

People and team structures with Team Topologies support:

- `Person` - Name, email, role
- `Team` - ID, name, type, members
- Team types: Stream-Aligned, Platform, Enabling, Overlay

Helper functions: `AllTeamTypes()`, `ValidTeamType()`

### Layer & Stage Types (`layer.go`)

Value stream layers and lifecycle stages:

**6 Layers:**

| Layer | Description |
|-------|-------------|
| Requirements | Product ideation, specs, design |
| Code | Application code, libraries, dependencies |
| Infrastructure | Cloud resources, networking, platform |
| Runtime | Running services, containers, workloads |
| Adoption | Product analytics, user engagement |
| Support | Customer support, incident management |

**5 Stages:**

| Stage | Description |
|-------|-------------|
| Design | Architecture, requirements, planning |
| Build | CI/CD, code quality, dependency management |
| Test | Testing coverage, quality assurance |
| Runtime | Production monitoring, availability |
| Response | Incident response, remediation |

Helper functions: `AllLayers()`, `ValidLayer()`, `AllStages()`, `ValidStage()`

### Maturity Levels (`maturity.go`)

5-level maturity model (M1-M5):

| Level | Name | Description |
|-------|------|-------------|
| M1 | Reactive | Ad-hoc processes, firefighting mode |
| M2 | Basic | Basic controls, individual-dependent |
| M3 | Defined | Standardized, repeatable processes |
| M4 | Managed | Data-driven, measured and controlled |
| M5 | Optimizing | Continuous improvement, automated |

Helper functions: `MaturityLevelName()`, `MaturityLevelDescription()`, `ValidMaturityLevel()`

### Framework Mappings (`framework.go`)

Compliance and security framework constants:

- **NIST Frameworks**: CSF, CSF 2.0, 800-53, 800-171, RMF, AI RMF
- **FedRAMP**: High, Moderate, Low baselines
- **Industry Standards**: ISO 27001, SOC 2, PCI DSS, HIPAA, GDPR
- **Security Frameworks**: MITRE ATT&CK, OWASP, CIS Controls
- **Operations**: DORA, SRE

Helper functions: `AllFrameworks()`, `NISTFrameworks()`, `FrameworkDisplayName()`

### Risk Types (`risk.go`)

Risk assessment primitives:

- `Risk` struct with ID, description, impact, probability, mitigation, status, owner
- Impact levels: Low, Medium, High, Critical
- Probability levels: Low, Medium, High
- Risk status: Open, Mitigated, Accepted, Closed

Helper functions: `AllRiskImpacts()`, `AllRiskProbabilities()`, `AllRiskStatuses()`

### SLI Types (`sli.go`)

Service Level Indicator type constants:

- `SLITypeAvailability` - Service uptime
- `SLITypeLatency` - Response time
- `SLITypeThroughput` - Requests per second
- `SLITypeErrorRate` - Error percentage
- `SLITypeFreshness` - Data staleness
- `SLITypeCorrectness` - Result accuracy
- `SLITypeCoverage` - Response coverage
- `SLITypeDurability` - Data persistence

Helper functions: `AllSLITypes()`, `SLITypeDirection()`

### Trend Types (`trend.go`)

Trend direction and analysis:

- `TrendInfo` struct with direction, magnitude, percentage
- Trend directions: Up, Down, Flat, Unknown

Helper functions: `AllTrendDirections()`

## Installation

```bash
go get github.com/grokify/prism-core@v0.1.0
```

## Usage

```go
import core "github.com/grokify/prism-core"

// Use domain constants
domain := core.DomainSecurity

// Check validity
if core.ValidDomain(domain) {
    fmt.Println("Valid domain:", domain)
}

// Get maturity level info
name := core.MaturityLevelName(3)        // "Defined"
desc := core.MaturityLevelDescription(3) // "Standardized processes..."

// Use framework constants
framework := core.FrameworkNISTCSF2
displayName := core.FrameworkDisplayName(framework) // "NIST CSF 2.0"
```
